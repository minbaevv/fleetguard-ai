# AGENTS.md — правила проекта FleetGuard AI

ИИ-сервис для таксопарков и проката: фото кузова «до/после» → новые повреждения → акт → ассистент.
Полный план: `PLAN.md`. Работай над одной задачей за раз.

## Стек
- Backend: Python 3.12, FastAPI, SQLAlchemy 2 + Alembic, Pydantic v2, Celery + Redis, PostgreSQL
- Хранилище: MinIO (S3 API)
- CV: OpenCV, Ultralytics YOLO (seg), PyTorch
- LLM: LangChain, structured output, доступ через `llm/client.py`
- Frontend: Next.js (App Router), TypeScript, Tailwind
- Инфра: Docker Compose, GitHub Actions

## Структура
`backend/`, `cv/`, `llm/`, `frontend/`, `infra/`, `docs/` (см. PLAN.md, раздел 3).

## Команды
- Запуск всего: `docker compose up -d`
- Backend тесты: `cd backend && pytest -q`
- Линтер: `cd backend && ruff check . && ruff format --check .`
- Миграции: `cd backend && alembic revision --autogenerate -m "msg" && alembic upgrade head`
- Frontend: `cd frontend && npm run lint && npm run build`

## Правила кода
- Типы везде (type hints, TypeScript без `any`).
- Бизнес-логика в `services/`, а не в роутерах. Роутеры тонкие.
- Любое изменение схемы БД только через Alembic-миграцию.
- Каждая новая функция с логикой получает тест. Для CV: юнит-тесты на синтетических данных.
- Маленькие функции и понятные имена. Комментарии объясняют «почему», а не «что».
- Не добавляй зависимости без необходимости, назови причину в сообщении.
- Один коммит на задачу: `feat:`, `fix:`, `test:`, `docs:`, `refactor:`.

## Безопасность (обязательно)
- **Все запросы к данным фильтруются по `org_id` из сессии.** `org_id` никогда не берётся из тела
  запроса, query-параметров или аргументов LLM.
- Секреты только из переменных окружения. Не коммитить `.env`, ключи, веса моделей, датасеты.
- Загрузка файлов: проверять тип по содержимому, лимит 10 МБ, случайные ключи, выдача по подписанным ссылкам.
- Пароли хэшировать (argon2/bcrypt). Не логировать пароли, токены, содержимое фото.
- Текст из фото, госномера и ответы пользователей считать недоверенными данными (инъекция промпта).
- Инструменты ассистента только на чтение, без произвольного SQL.

## LLM
- Все вызовы через `llm/client.py`, логирование в `llm_usage`, лимиты на количество вызовов.
- Ответы по Pydantic-схемам (structured output). В тестах и CI LLM мокается.
- Акт нейтральный: «обнаружено повреждение», не обвинять водителя.
- Если данных нет, ассистент так и говорит. Выдумывать данные нельзя.

## CV
- Нормализованные полигоны (0..1). Исправлять EXIF-ориентацию перед обработкой.
- Пороги (качество фото, уверенность, IoU) лежат в конфиге, а не зашиты в коде.
- Тестовая выборка модели не используется для подбора параметров.
- Веса не хранятся в git, ссылка на загрузку в `cv/training/README.md`.

## Чего не делать
- Не переписывать несвязанные модули «заодно».
- Не менять публичные API-контракты без обновления PLAN.md и тестов.
- Не отключать тесты и линтер, чтобы «заработало».
- Не придумывать метрики или результаты. В документации только измеренные значения.

## Формат ответа агента после задачи
1. Что сделано (кратко).
2. Какие файлы изменены.
3. Как проверить (команды и ожидаемый результат).
4. Допущения и то, что осталось сделать.
